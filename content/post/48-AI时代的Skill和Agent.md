最近被问到一个问题："你天天说的 Skill 和 Agent 到底是什么？它们有什么区别？"——问的人不是程序员，而是一个对 AI 感到好奇但完全不懂代码的人。

这其实是个非常好的问题。这两个词在 AI 圈子里被频繁使用，但解释往往一上来就堆术语，对非技术人员来说跟没解释一样。所以这篇文章，我试着用最日常的语言把这两个概念讲清楚。

## 先从一个厨房的故事说起

想象你开了一家餐厅。

你有一本**菜谱**，上面写着："番茄炒蛋——先热锅，倒油，油热后下打散的鸡蛋，翻炒至凝固盛出；再加少许油，下番茄块炒出汁，倒回鸡蛋，加盐调味，出锅。"

你还有一个**厨师**，他会看菜谱做菜，也会根据食材情况调整火候，还能在你不在的时候自己决定今晚做什么菜。

在这个故事里：

- **菜谱**就是 Skill
- **厨师**就是 Agent

是不是已经有点感觉了？我们展开说。

## Skill：一份精确的"行动指南"

Skill，直译是"技能"，但在 AI 的语境里，它更像是一份**精心编写的行动指南**——告诉 AI 在特定场景下应该怎么做。

回到菜谱的类比：一份好的菜谱不会只写"做个番茄炒蛋"，它会详细说明每一步的操作、注意事项和判断标准。AI 的 Skill 也是如此。

### 一个真实的 Skill 长什么样？

假设你是一个运营，想让 AI 帮你审查一篇即将发布的推文，你可以随手说"帮我看看这篇文案"，但结果往往很随意。如果你写成一个 Skill，大概是这样：

> **你的角色**：你是一位资深新媒体运营，擅长内容审核和优化。
>
> **审查步骤**：
> 1. 先检查是否有错别字和语病
> 2. 再看标题是否有吸引力、是否含关键信息
> 3. 然后检查是否符合品牌调性（用词、语气）
> 4. 最后检查是否涉及敏感内容或合规风险
>
> **输出格式**：按严重程度排列问题，每个问题给出具体位置和修改建议。
>
> **注意事项**：不要为了挑毛病而挑毛病，要区分"风格偏好"和"真正的问题"。

看到了吗？Skill 的本质就是**把你的经验和方法论写成一份清晰的指令**，让 AI 每次都能按照你的标准来执行，而不是每次都凭"心情"给出参差不齐的结果。

### 怎么写好一个 Skill？

写好 Skill 的核心原则，和写好一份菜谱是一样的：

**1. 说清楚目标**

"做个菜"不是好菜谱，"做一道酸甜口的番茄炒蛋"才是。同样，"帮我写篇推文"不是好 Skill，"写一篇面向 25-35 岁职场女性的产品种草推文，语气轻松不油腻，控制在 800 字以内"才是。

**2. 给出步骤，而不是含糊的要求**

差的写法："审查一下这篇推文，注意质量。"

好的写法：把审查拆成具体步骤——先看错别字、再看标题、然后看合规性、最后看调性。就像菜谱写"先热锅再倒油"，而不是"随便炒炒"。

**3. 告诉它边界和禁区**

菜谱会注明"不要用铁锅炒番茄"（酸性食物会破坏铁锅涂层），Skill 也需要注明禁区。比如"不要使用绝对化用语""不要引用未经核实的数据"。

**4. 提供判断标准**

菜谱说"炒至鸡蛋凝固"——这就是一个判断标准。Skill 也要给出判断标准："如果标题超过 20 个字，建议精简""如果有'最''第一'等绝对化用语，标记为合规风险"。

**5. 用例子说话**

与其费劲描述，不如直接给一个期望输出的例子。就像菜谱旁边配一张成品照片，一目了然。

总结成一句话：**写 Skill 就像带新人——你交代得越具体，结果越靠谱。**

## Agent：一个能自主行动的"智能助手"

如果 Skill 是菜谱，那 Agent 就是那个能看懂菜谱、还能自主做决策的厨师。

Agent 的核心特征是**自主性**。它不只是被动地执行一条指令，而是能：

- **理解目标**：知道你要达成的最终结果是什么
- **制定计划**：自己拆解步骤，决定先做什么后做什么
- **使用工具**：根据需要调用不同的能力（搜索资料、查数据、生成图表……）
- **应对变化**：遇到问题能调整策略，而不是一条路走到黑
- **判断何时完成**：知道什么时候任务算做完了

### 一个具体的例子

你说："帮我分析一下这个月社群的运营数据，如果关键指标下滑超过 10% 就告诉我原因。"

- 如果只是执行一条简单指令（Skill 模式），AI 可能会把数据表格原样贴给你，加一句"请自行查看"。
- 如果是 Agent，它会：先找到数据源 → 整理关键指标 → 对比上月数据 → 识别下滑指标 → 分析可能原因 → 判断是否超过 10% 阈值 → 只把异常指标和原因整理好告诉你。

Agent 会自己规划路径，遇到数据缺失能换一个维度分析，最终给你一个完整的、经过思考的结果。

## Skill 和 Agent 的核心区别

用一张表说清楚：

| | Skill | Agent |
|---|---|---|
| **类比** | 菜谱 | 厨师 |
| **本质** | 一份指令/规范 | 一个能自主行动的执行者 |
| **自主性** | 低——你说什么它做什么 | 高——它能自己规划、决策 |
| **灵活性** | 低——只适用于特定场景 | 高——能应对意料之外的情况 |
| **可控性** | 高——每一步都在你预料之中 | 较低——它可能走出你没想到的路径 |
| **写法** | 详细的步骤和规则 | 目标 + 可用工具 + 边界条件 |
| **适合场景** | 重复性的、有固定流程的任务 | 复杂的、需要灵活应变的任务 |

### 一个直观的对比

**用 Skill 的方式做晚餐**：

你翻开菜谱，一步一步照着做。菜谱写什么你就做什么，结果稳定可控，但如果发现冰箱里没有番茄，你就卡住了——菜谱没写这个情况怎么办。

**用 Agent 的方式做晚餐**：

你跟厨师说"今晚做两菜一汤，清淡一点"。厨师自己去冰箱看有什么食材，决定做什么菜，发现番茄没了就用别的替代，调整菜单，最终端出一桌符合要求的菜。结果可能超出预期，也可能和你的想象不完全一样。

## 它们的关系：不是替代，是配合

Skill 和 Agent 不是非此即彼的关系。实际上，**好的 Agent 会使用 Skill**。

还是那个厨房：一个优秀的厨师（Agent）不会每次都从零开始发明做法，他会参考菜谱（Skill），在菜谱的基础上根据实际情况灵活调整。

在 AI 工具中也是一样：Agent 在执行复杂任务时，会根据场景选择合适的 Skill 来调用。比如一个运营 Agent 可能在写推文时调用"文案审核 Skill"，在发活动时调用"活动清单 Skill"，在复盘时调用"数据分析 Skill"。

**Skill 提供经验和规范，Agent 提供判断力和执行力。** 两者结合，才是 AI 最强大的工作方式。

## 最后总结

- **Skill** = 一份精心编写的行动指南，让 AI 在特定场景下按你的标准执行。写好 Skill 的关键是：说清目标、给出步骤、标明禁区、提供标准、用例子说话。
- **Agent** = 一个能自主理解目标、规划步骤、调用工具、应对变化的智能助手。它的核心是自主性和判断力。
- **区别**：Skill 是"怎么做"的说明书，Agent 是"去做"的执行者。Skill 强调可控和一致，Agent 强调灵活和自主。
- **关系**：Agent 可以调用 Skill，就像厨师可以参考菜谱。两者配合才是最优解。

如果还是觉得抽象，就记住这一句话：**Skill 是你教给 AI 的方法，Agent 是 AI 用这些方法帮你干活的能力。**
